# Review: gl.plot.network (dartR.captive)
- Family mode: analysis (plotting)
- Date: 2026-09-23
- Reviewer: Claude (claude-opus-5-5), dartr-function-review v2.0.0
- Package commit: 3e87a84 (origin/dev)
- Datasets: platypus.gl (first 20 individuals; `gl.grm()` and Euclidean `gl.dist.ind()` matrices); simulated populations of 100 and 300 individuals (`dartR.sim::gl.sim.ind`)
- Baseline: tests/testthat/test-gl.plot.network.R (snapshot captured pre-review, 3 expectations). The function draws a base-graphics plot and returns `NULL`, so the baseline records errors and the return value; the plot content was checked by recomputing the kept links and widths outside the function.

## Verdict

**Standards: Needs work** — no roxygen `@name`/`@title`/`@family`, error
messages name an old function (`gl.dist.network`), the plot cannot be
saved or returned, and the pair table is built with a double loop.
**Spec: Rework** — the documented default (`x = NULL`) always errors;
the function is documented for distance matrices but keeps the largest
values, i.e. the least related pairs of a distance matrix; and edge
widths are taken from the wrong pairs.

## Findings

**F1 [HIGH, confidence: high] — the documented default `x = NULL` always
errors (DOC5)**
`R/gl.plot.network.r:96` — `utils.check.datatype(x)` runs before the
`is.null(x)` branch, so `gl.plot.network(D)` stops with "inappropriate
object passed to function, found NULL"; the code that handles `x = NULL`
(one colour, no legend) is unreachable.
Proposed change: check the datatype only when `x` is given.

**F2 [HIGH, confidence: high] — distance input shows the least related
pairs (DOC5; inverted-filter class)**
`R/gl.plot.network.r:171-173` — links are kept when their value is at or
above the `1 - alpha` quantile. The title, `@description` and `@param D`
say D is a distance matrix ("generated by dist() or gl.dist()"), for
which large values mean distant individuals; the example and the
"relatedness measures above the quantile" text assume a similarity
matrix (`gl.grm`).
Failure scenario: 20 platypus, Euclidean `gl.dist.ind()`, `alpha =
0.05`: the 12 kept links have mean distance 18.9 against 17.6 overall;
the closest pairs (from 15.4) are never drawn.
Proposed change (member's choice): (a) add `type = c("similarity",
"distance")`; for distances keep the links at or below the `alpha`
quantile; default "similarity" keeps current behaviour for GRM users and
the docs are corrected; or (b) decide from the class: `dist` objects as
distances, matrices as similarities.
**Consequence of (a): no change for existing calls; distance users must
set `type = "distance"` to get the closest pairs. Of (b): calls with a
`dist` object now show the closest pairs instead of the most distant.**

**F3 [HIGH, confidence: high] — edge widths belong to other pairs
(PLT3)**
`R/gl.plot.network.r:201` — `edge.width = links$weight` passes the
weights of all pairs, while only the kept edges are drawn; igraph uses
the first values. The kept edges get widths 18.25, 18.63, 18.25 where
their own weights are 19.03, 18.76, 19.24; with a GRM, where 145 of 190
values are negative, drawn edges can get negative widths. Raw distances
(~18) also give very thick lines.
Proposed change: width from the kept edges' own weights, rescaled to a
fixed range (e.g. 0.5-4), strongest link widest.

**F4 [MEDIUM, confidence: high] — quadratic pair loop (STY2)**
`R/gl.plot.network.r:136-146` — the link table is filled cell by cell in
a double loop: 100 individuals 0.3 s, 300 individuals 10.7 s; 1,000
would take minutes.
Proposed change: build it from `which(upper.tri(m), arr.ind = TRUE)` in
one step. Same links.

**F5 [MEDIUM, confidence: high] — no check that D matches x (FS5)**
Names of `D` not in `x` stop inside igraph ("Some vertex names in `d` are
not listed in `vertices`"); a `D` smaller than `x` adds isolated nodes.
Proposed change: stop with a clear message unless `D` is square with
names equal to `indNames(x)` (as done in `gl.grm.network`, PR #97).

**F6 [LOW, confidence: high] — messages and housekeeping (VRB, FS3,
FS5)**
Errors mention "gl.dist.network"; `report(report(...))`; `method` is
checked with `||` (a vector errors) and an invalid value silently
becomes "fr"; `build = "Jody"`; `alpha` is described as "Upper threshold"
but is the proportion of links drawn.
Proposed change: correct messages; `match.arg(method)`; document `alpha`
as the proportion of links drawn.

**F7 [LOW, confidence: high] — documentation (DOC1, DOC7)**
No `@name`, `@title` or `@family` tags (the first sentence is used);
`@return` "no value (i.e. NULL)"; `@author` has no `Author(s):`.
Proposed change: add the tags; return the igraph object (kept links)
invisibly and document it, so users can inspect which pairs were drawn.
**Consequence: the return value changes from NULL to an igraph object
(invisible).**

**F8 [INFO] — the Shiny tool cannot work**
dartr2shiny calls `gl.plot.network(method = ..., node.size = ..., ...)`
without `D` or `x`, so it always stops with "argument "D" is missing";
a dartr2shiny fix is needed (not in this repository).

## Proposed changes

1. Datatype check only when `x` is given (F1).
2. Distance vs similarity: (a) `type` argument, default "similarity"; or
   (b) by class (F2).
   **Consequence of (b): `dist` input shows the closest pairs instead of
   the most distant.**
3. Edge widths from the drawn edges' own weights, rescaled (F3).
4. Vectorised link table (F4).
5. Check D against x (F5).
   **Consequence: mismatched names error with a clear message.**
6. Messages, `match.arg(method)`, `alpha` wording (F6).
   **Consequence: an invalid `method` errors instead of using "fr".**
7. Roxygen tags; return the network invisibly (F7).
   **Consequence: returns an igraph object instead of NULL.**

## Outcome

All seven approved changes applied to `R/gl.plot.network.r` on
2026-09-23; `devtools::document()` run. `tests/testthat/test-gl.plot.network.R`:
9 expectations pass; the pre-change baseline tests were replaced by tests
of the approved behaviour.

- Existing calls unchanged: on a GRM of 20 platypus with `alpha = 0.05`,
  the drawn links are exactly those of the old logic (10 links).
- Change 1 (F1): `gl.plot.network(G)` without `x` returns the network and
  draws single-colour nodes.
- Change 2 (F2, option a): `type = "distance"` keeps the alpha proportion
  of the lowest values; on the Euclidean matrix the 11 kept links are all
  at or below the 5% quantile (16.16) and include the closest pair
  (15.36). `type` is the last argument before `verbose`, so positional
  calls are unaffected.
- Change 3 (F3): widths from each drawn link's own strength, rescaled to
  0.5-4.
- Change 4 (F4): link table built from `which(upper.tri())`; 300
  individuals 0.14 s (was 10.7 s).
- Change 5 (F5): mismatched names error "The row and column names of D
  must be the individual names of x".
- Change 6 (F6): `match.arg()` for `method` and `type`; messages no longer
  mention `gl.dist.network`; `alpha` documented as the proportion of pairs
  drawn; 0 lines printed at `verbose = 0`.
- Change 7 (F7): `@name`, `@title`, `@family`, `Author(s)`; returns the
  drawn igraph network invisibly.
- The `@examples` block runs.
- Not in this change: the dartr2shiny call without `D`/`x` (F8).
- PR #106 (`review-gl.plot.network` -> `dev`).
